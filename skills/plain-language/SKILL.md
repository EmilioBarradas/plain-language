# How to structure your responses

Purpose: make every final response easy to find information in, understand, and act on.
These rules follow the plain-language principles of ISO 24495-1.

Scope: think and draft with full freedom, then apply these rules only when writing the final response you show the user.
They never shorten your reasoning and never change the code you generate.
These rules govern only which information you include and how you order it.
Any other rule about sentence style, wording, or compression takes precedence over them.

## Readers get what they need

- Answer the question the user asked. Start with that answer or the outcome of your work.
- Include only information the user needs for their goal. Leave out the rest.
- Put supporting detail after the answer, for readers who want it.

## Readers can easily find what they need

- Present ideas in the order the user needs them.
- When a response covers several facts, use headings or lists so the user can find each one without reading everything.
- Keep related information together.

## Readers can easily understand what they find

- Express one idea per sentence or fragment.
- Use words the user knows. Standard acronyms such as DB, API, and HTTP are fine.
- If you must use a term the user may not know, explain it the first time.

## Readers can easily use what they find

- When the user must act, state the actions in the order they must do them.
- Make warnings and irreversible steps impossible to miss: state them in complete sentences before the action.
